最近两天花了大概八个小时，终于把QQ机器人搭建起来了，写一个帖子来庆祝一下。

## 项目概述

这个项目的目的是搭建出一个QQ机器人，能够根据指令进行各种各样的操作。
并且准备全程使用AI协作，所有代码与思路均由AI提供。
使用 NapcatQQ 框架管理机器人，通过 VS Code 写后端代码。
功能就是想到什么就写什么，没有固定功能。
准备后面部署到服务器，使得机器人能够24小时运转。
机器人会连接 DeepSeekAPI 使自己更智能化，使用 deepseek-v4-flash 模型。

## 搭建过程

### 连接前后端

第一步是用一个协议控制我的QQ小号，使得程序能够收到别人发的消息或者发送消息。
我用的是 NapCatQQ，并且用的是 Desktop 版，这样更方便图形化管理。
扫码登录QQ之后，程序就能控制我的QQ收发消息了。
接下来要在 Linux 系统里面安装 NapCatQQ 了，和 Windows 里面的 NapCatQQ 连接。
使得 Windows 系统里面的 NapCatQQ 收到消息之后还能转发给 Linux 系统。
我用的是 VS Code 里面的 WSL2，而且是 Ubuntu。
这一切都弄好之后，前后端的连接就完成了。

### 写插件

在 Linux 系统里面安装好 NapCatQQ 之后，就可以在 `plugins/` 里面写插件了。
所谓插件，其实就是一个个程序，使得机器人在收到特定消息的时候能够按照插件里面的代码执行。
插件都是我拿 AI 写的，我把一些细节跟 AI 说了一下，AI 就给我写出来了。
目前写了签到插件、AI 对话插件、拦截私聊消息插件、help 插件和静态博客更新提醒插件。

### 建立隧道并将隧道设置为开机自启

至此，除了静态博客更新提醒插件，其他插件都能正常运行。
因为如果要实现静态博客更新后提醒，就需要我的机器人的 API。
可是机器人的 API 需要公网 IP，我的机器人只能运行在内网里面。
所以需要将我的机器人映射到公网里面去。
然后我发现，cloudflare 竟然还有免费的隧道服务。~~cloudflare怎么什么都有~~
我正好还有一个域名，所以我就用了二级域名(bot)进行映射，用 cloudflareDNS 解析我的域名。
映射成功之后，还需要把隧道设置为开机自启模式。
总之在 cloudflare 官方文档和 Gemini 的帮助下，我完成了隧道的构建和开机自启。

## 遇到的问题

### QQ号被封

在几个月前，我就尝试过打通前后端，并且成功了，虽然插件没写好。
但是可恶的腾讯竟然在第二天就把我小号封了，理由是疑似脚本操作。
没办法，只好手动解封然后又养了一段时间，一直到现在，不知道后面上服务器会不会被封。

### QQ版本过高

QQ最新版是9.9.32，但是 NapCatQQ 框架不能支持这个版本。
NapCatQQ 官方网站里面的QQ下载链接打不开，所以我自己在网上找了一个9.9.26的版本。
下载了旧版之后，NapCatQQ 框架就可以操控我的QQ小号了。

### 插件加载失败

`bot.py` 开始运行之后，我发什么消息都没反应，尽管后端显示已经收到了消息。
起初我以为是插件代码写的有问题，所以我往里面加了一行代码

~~~python
logger.info("👉 [签到插件] 文件已被 NoneBot 成功加载！")
~~~

结果这句话没有在终端里面显示，说明这个插件根本就没有加载。
最后发现是因为程序只会在工作区目录下的文件夹里面寻找插件加载。
将工作区切换到内层文件夹就好了，此时插件可以顺利加载。
![插件顺利加载](https://cdn.tqw740.top/2026-07-25-17-13-52.png)

### 消息被无关插件拦截

这个问题遇到过很多次了，原因是插件的优先级没设置好或者代码写的有问题。
举个例子，假如说私聊消息拦截插件优先级最高，处理所有私聊与群聊消息。
然后设置了阻断器，阻断后续对消息的操作。
这样的话，群聊消息也会被阻断，导致机器人不能做出任何反应。
所以需要让插件只允许群聊消息通过，不做任何处理，阻断其他消息。
同理，假如 help 插件的优先级比 AI 对话插件的优先级更低。
用户输入`/help`时，会触发 AI 对话插件。
（不过这里的 AI 对话插件也有问题，应该是只在被@时触发）
这样来看，AI 对话插件的优先级需要比较低。
